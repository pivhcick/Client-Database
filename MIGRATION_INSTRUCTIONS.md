## Дата: 2026-01-29
## Автор: Claude Code

## Что изменяется

### До миграции:
- Все пользователи организации видели ВСЕ компании организации
- Не было разграничения прав доступа между admin и regular пользователями

### После миграции:
- **Администраторы (admin)** видят ВСЕ компании организации
- **Обычные пользователи (regular)** видят ТОЛЬКО свои компании (где они `created_by_user_id`)

## Пошаговая инструкция по применению

### Шаг 1: Backup базы данных (ОБЯЗАТЕЛЬНО!)

Перед применением миграции создайте резервную копию базы данных:

1. Откройте Supabase Dashboard
2. Перейдите в раздел "Database" → "Backups"
3. Нажмите "Create backup"
4. Дождитесь завершения создания backup

### Шаг 2: Применить SQL миграцию

1. Откройте [Supabase SQL Editor](https://supabase.com/dashboard/project/rcprdyenxwotgdanrycu/sql/new)

2. Скопируйте ВЕСЬ код из файла `supabase_migration_company_role_access.sql`

3. Вставьте код в SQL Editor

4. Нажмите "Run" (или Ctrl/Cmd + Enter)

5. Дождитесь выполнения всех команд

6. Убедитесь, что все функции созданы успешно (не должно быть ошибок)

**Ожидаемый результат:**
```
Success. No rows returned
```

### Шаг 3: Проверить созданные функции

Выполните следующий запрос для проверки:

```sql
SELECT
  routine_name,
  routine_type,
  data_type
FROM information_schema.routines
WHERE routine_schema = 'public'
  AND routine_name IN (
    'get_companies',
    'get_companies_filtered',
    'search_companies',
    'get_company_by_id',
    'update_company',
    'delete_company'
  )
ORDER BY routine_name;
```

**Ожидаемый результат:** 6 строк с именами функций.

SELECT
  c.id,

  c.created_by_user_id,
  u.first_name || ' ' || u.last_name as creator

## Часто задаваемые вопросы (FAQ)

### Q: Что произойдет с существующими компаниями?
**A:** Все существующие компании останутся в базе данных. Изменится только логика их отображения:
- Компании, созданные до миграции, будут иметь `created_by_user_id` того пользователя, который их создал
- Regular пользователи будут видеть только те компании, где они указаны как `created_by_user_id`
- Admin пользователи будут видеть все компании организации

### Q: Может ли admin редактировать компании других пользователей?
**A:** Да, администраторы имеют полный доступ ко всем компаниям организации (просмотр, редактирование, удаление).

### Q: Может ли regular пользователь передать компанию другому пользователю?
**A:** Нет, в текущей реализации нет функции передачи компании. Поле `created_by_user_id` устанавливается при создании и не изменяется. Если нужна такая функция, потребуется дополнительная разработка.

### Q: Что если regular пользователь попытается открыть direct link к чужой компании?
**A:** Приложение вернет ошибку "Компания не найдена или доступ запрещен". RPC функция проверит права доступа и не вернет данные.

### Q: Влияет ли эта миграция на контактные лица, историю контактов или напоминания?
**A:** Нет, эта миграция затрагивает только таблицу `companies` и связанные RPC функции. Контактные лица, история контактов и напоминания наследуют доступ через связь с компанией (если пользователь видит компанию, он видит и связанные с ней данные).

### Q: Нужно ли обновлять мобильное приложение для всех пользователей?
**A:** Да, обязательно! Старая версия приложения не будет работать корректно с новыми RPC функциями (будут ошибки из-за несоответствия параметров). Рекомендуется:
1. Применить миграцию в нерабочее время
2. Оповестить пользователей о необходимости обновления
3. Опционально: принудительно обновить APK через MDM или push-уведомление
